# Phase 2 red-team review (2026-10-02)

Independent adversarial review of `fix/phase2-no-silent-loss` at 906f6eb (W6 one write path and sequence repair; W8a per-database OPFS pools, manifest and leader failover; W3/W4 engine; W5 server delivery, liveness and Postgres integrity; RT-31..RT-34). Every finding has a repro under `tests/repro/` that fails at 906f6eb, and is tracked in `remediation/tracker.json` as RT-35..RT-41.

Method:
- Executable repros against the real `KoraSyncServer`, `TestDevice` (real SQLite store and `SyncEngine`) and in-memory transports.
- Postgres 16 runs for the server store paths: RT-37 also fails with `KORA_REPRO_STORE=postgres`.
- A mixed-version harness: the beta.13 build (33bca46) for client and server, against this branch (scratch, not committed).
- Seeded chaos runs (drop, duplicate and reorder):
  - the no-silent-loss invariant suite with 8 extra seeds;
  - an atomic-increment exactly-once workload with simulated upgrade re-uploads (prefix reset) mid-run.

## What held up

- **Upload ordering vs ack (attacked first).** I tried to make the ack of a timestamp-ordered batch cover an unprocessed op. The setup was two tabs on one node with skewed HLCs, plus a transient validator throw. It is closed, because `sendUpload` sorts each batch by `(node, seq)` (`compareForUpload`), and acks resolve only the named batch.
- **Exactly-once atomic increments.** Increments stayed exactly-once under 20% drop, duplicate and reorder, with prefix resets (simulated upgrade re-uploads) mid-run. All replicas and the server matched the issued total (4 seeds). Pending counts drain once the network calms.
- **No-silent-loss invariants.** The U (prefix), D (watermark) and C (convergence) invariants held on 8 extra seeds (101..808).
- **Mixed versions, Phase 2 clients on a beta.13 server.** These converged with no loss under chaos (4 seeds).
- **Mixed versions, beta.13 clients on the Phase 2 server.** One seed out of five lost a beta.13 op. beta.13 clients lose ops under chaos against the beta.13 server too (SYNC-4 class, fixed by upgrading the client), so this is not attributed to Phase 2 server code.
- **Dedup before auth (RT-31).** It is not a bypass. The own-node fast path requires the stored op to be under the session's own claimed node. A foreign op is acked only for the exact stored `(node, seq, id)`, which needs a 256-bit id from outside the attacker's scope.
  - Caveat: the server never checks `id == hash(content)`, so content addressing is client-trusted. No exploit was found, but it should be verified at ingest.
- **Accepted-scope resume (RT-33).** A forged `acceptedScopeKey` or watermark can only make the forging client skip part of its own stream, or restart it. Filtering always uses the scope resolved now, and a watermark above the frontier resets to 0. There is no disclosure and no skip for others.
- **`SEQUENCE_CONFLICT` cannot be used against another device.** That would require uploading under its node, which the node claims refuse. Outside RT-37, conflicts arise only from the device's own state (RT-35).
- **Legacy duplicate pairs.**
  - A second op delivered to a client under an occupied `(node, seq)` goes to `_kora_seq_conflicts` and still folds.
  - A renumbered own op is acked as a duplicate.
  - The epoch logic and the partial index behave on Postgres 16 (`sequence-enforcement-epoch.test.ts`, `ingest-integrity.test.ts`: 23/23 with `KORA_PG_TEST_URL`).
- **Legacy-pool migration.** sqlite-wasm's `importDb` associates the file name only after all bytes are written, so a page killed mid-copy leaves no half database under the name. The legacy copy is unlinked only after `quick_check` on the import.
- **Backpressure and liveness.** The delivery stream polls `bufferedAmount` on WS and HTTP, and any inbound message (delivery acks) counts as liveness for the server ping. No busy-client kill was found by reading the code; it was not run against a throttled link.
- **Phase 1 security fixes.** `scripts/remediation/check.mjs --all` (node, Postgres, Chromium) shows no regression of RT-1..RT-34.
- **Not attacked** (no time, or covered by existing W8a real-Chromium checks):
  - follower transaction during leader failover;
  - freeze/pagehide release;
  - `deleteDatabase` while another tab writes.
