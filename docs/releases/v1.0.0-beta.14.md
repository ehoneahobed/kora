# Kora.js 1.0.0-beta.14

**Not breaking at the protocol or storage level.** Upgrade every `korajs` and `@korajs/*` package
to `1.0.0-beta.14` together, sync servers first. A beta.12 deployment can upgrade straight to
beta.14 with the [upgrade guide](../guide/upgrading-to-beta13.md); what changed since beta.13 is
in its section [From beta.13 to beta.14](../guide/upgrading-to-beta13.md#from-beta-13-to-beta-14).

```bash
pnpm add korajs@1.0.0-beta.14 @korajs/server@1.0.0-beta.14   # and every other @korajs/* package you use
```

## Highlights

- **beta.12 upgrades need no bind script (F1).** A signed-in device presenting a node id with
  history but no owner (beta.12 recorded no node claims), or one an administrator released,
  claims it when the node id equals the device id the auth provider verified for that user, in
  one atomic store step (`ServerStore.claimUnownedNode`). The device reconnects and its queued
  offline writes upload. Another user presenting the node id is still refused. Logged as
  `node_claim.handover`; `deviceNodeHandover: false` restores the beta.13 refusal. Writes a
  beta.12 user made before the page first reloaded after sign-up are held as `unassigned` until
  the app assigns them, instead of staying in the queue unreported.
- **Presence across different grants (F16).** A presence state whose cursor names a record
  reaches every session that can read that record, decided on the latest stored row and decided
  again when the record changes. A "who is online" state without a cursor stays within the
  identical download scope.
- **Grants change at once.** `refreshScopes(userId)` re-resolves a user's grant on every live
  session after a membership change; `maxScopePredicateValues` raises the 100-value `$in` limit
  (F17, benchmarked to 5,000).

## Security and data safety

- A delivery pass's prefetched rows no longer leak into decisions running meanwhile ([advisory](./security-advisory-beta14.md)). In beta.13 a
  Yjs doc update could be authorized against a row read before the record moved out of the
  writer's grant, and reach the new owner's devices; reference checks and presence could use such
  a row too.
- Operational endpoints with no token answer `403` in production (F5).
- The warning for signed-in servers that share every user's data is back, with
  `unscopedSharing: 'warn' | 'allow' | 'refuse'` (F4).
- A browser shared by two users cannot store one user's writes as the other's (F9,
  `NODE_OWNED_BY_ANOTHER_USER`); `NODE_ID_CLAIMED` says whether the node has another owner.
- The rich-text controller never drops local edits (`retrySave()`, `hasUnsavedChanges`).
- A unique constraint's `where` selects the records compared, on devices and on the server.

## Fixes from the beta.13 rollout

- `defineSchema` refuses constraint `where` clauses that can never match (F2).
- `importBackup` converts version-1 backups itself (F3).
- One operation size default on device and server, pinned by a test (F6).
- `spaFallback: 'extensionless'` for service-worker route warming (F7).
- One default database location for every template; the SQLite stores create its directory
  (F8, F10).
- `PostgresUserStore.close()` (F11).
- `undefined` inside a json value is written as JSON writes it (F12a); how to change one key of a
  json field is documented (F12b).
- `/health` reports the real server version (F13).
- `findJsonStringValues(store)` finds legacy json rows holding encoded strings (F14).
- A `sqlite3.wasm` that cannot load fails the open in seconds and can be retried (F15).

## Deprecations kept

Protocol 1 (beta.12 clients), `experimental.legacyMerge` and the `allowLegacyAnonymousClaims`
default of `true` remain, deprecated. beta.13 announced their removal for the next release;
beta.14 keeps them because each would break part of the beta.12 upgrade path it completes. The
release that removes them will say so.

## Verification

- Every fix ships with a test that failed on the previous code.
- `scripts/remediation/compat-beta12-auth-browser.mjs` and
  `scripts/remediation/compat-beta12-template-browser.mjs` upgrade a beta.12 `@korajs/auth` app in
  Chromium, on SQLite and Postgres 16, with no bind script: the second scaffolds the app with
  beta.12's CLI, queues a write typed while the server is down, upgrades the packages and checks
  the write uploads and that a second user is refused the node. Results:
  [remediation/evidence/compat-beta12.md](https://github.com/ehoneahobed/kora/blob/main/remediation/evidence/compat-beta12.md).
