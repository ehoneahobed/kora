# Kora.js 1.0.0-beta.11

Beta.11 hardens authenticated, multi-tenant, offline-first applications on shared devices and
constrained networks.

## Highlights

- Authenticated-only sync waits for auth restoration and stays suspended while signed out.
- `AuthBoundKoraProvider` serializes per-user app/store replacement and closes the old app first.
- `app.storeInfo()` reports the active database identity and durability.
- Query-driven partial sync supports `reactive`, `static`, and `disabled` policies, semantic
  canonicalization, containment, and safe broad-to-narrow watermark inheritance.
- `waitForSettled()` distinguishes upload acknowledgement from active-view download completion.
- Sync status includes phase, frontier/completeness, in-flight work, and active apply failures.
- Server-authoritative scopes support canonical, bounded `$in` predicates; empty `$in` denies.
- `@korajs/test` includes controllable auth transitions and connection/message/byte counters.

## Compatibility notes

- `namespaceByAuthUser` remains available. For live user changes, React applications should use
  `AuthBoundKoraProvider`; same-user token and scope refreshes do not replace the app.
- Reactive query subsets remain the compatibility default.
- Query-view changes use the compatible reconnect path. Servers that do not implement an in-band
  view-update protocol continue to work.
- Existing equality scopes remain valid.
- New detailed status fields are additive.

## Release sign-off

Run from the repository root:

```bash
pnpm install --frozen-lockfile
pnpm test:pre-release
pnpm release:dry-run
```

Manual browser checks should cover signed-out boot, A → signed out → B without reload, offline
queue isolation, redundant route queries, settlement, and a two-partition `$in` scope.

## Publish

The package manifests are already set to beta.11. Do **not** run `pnpm beta:bump` or
`pnpm beta:release`; either command advances them to beta.12.

1. Commit the release changes on a branch and ensure CI is green on that exact commit.
2. Run `pnpm release:dry-run`. This builds the workspace and locally packs every publishable
   package without writing to the registry.
3. Choose one publish path from the [npm publish checklist](./npm-publish-checklist.md). Merging to
   `main` triggers the release workflow; alternatively, an authenticated maintainer can run
   `pnpm release` locally when that workflow will not publish concurrently.
4. Verify `npm view korajs@1.0.0-beta.11 version` and `npm view korajs dist-tags`, then repeat the
   version check for the scoped packages.
5. Tag the released commit as `v1.0.0-beta.11`, push the tag, publish these release notes, and
   announce beta.11.

The publish set is `korajs`, `@korajs/auth`, `@korajs/cli`, `@korajs/core`,
`@korajs/devtools`, `@korajs/merge`, `@korajs/react`, `@korajs/server`, `@korajs/store`,
`@korajs/svelte`, `@korajs/sync`, `@korajs/test`, and `@korajs/vue` at `1.0.0-beta.11`, plus
`create-kora-app@0.1.25-beta.10` and `@korajs/tauri@0.4.3-beta.10`.
