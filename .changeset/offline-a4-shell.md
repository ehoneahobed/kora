The offline app shell reports whether it is really there. The worker generated by `koraServiceWorker()` answers `KORA_SW_STATUS` after checking every precached URL, and when online refetches a missing one past the HTTP cache and stores it only if its SHA-256 equals the digest recorded at build time (a newer deployment's bytes are never stored, the entry stays missing); it also compares the page's hashed scripts and styles with its own build (`other-build`) and records the URLs it could not serve (`misses`, bounded). The registration script publishes `globalThis.__KORA_SHELL__ = { v: 1, state, version, misses }` and a `kora:shell` event (checked at start, on `updatefound`, `controllerchange` and `visibilitychange`, never polled), and `app.offline.status().shell` reads it: `installing`, `installed`, `not-installed`, `other-build`, `unsupported`, `bundled` (a native-storage desktop build) or `none` (no plugin, `vite dev`, or an older `@korajs/cli`: update both). All 13 templates, `tauri-react` included, render an `<OfflineBadge />` built on `useOfflineReady()` ("Available offline", "Preparing offline copy... 40%", "Not available offline yet"; first reason as the tooltip), on by default and not rendered in `vite dev`.
