`kora doctor` grows the rest of D1 and D6. A new `schema-duplicates` check warns, with file paths and lines, when more than one `defineSchema()` call declares the same collection names (a client schema and a server schema written twice drift apart); the fix is to export one schema and import it from the client, the sync server and `kora.config.ts`, which every bundled template already does and now a test enforces for all 13. `kora doctor --db <database> --dry-run-migrations` runs the migrations the database has not recorded against a copy of the file (SQLite) or inside a transaction that is rolled back (Postgres, with `statement_timeout` and `lock_timeout` guards), and reports each step, the rows it touches, the measured duration and, on Postgres, the locks held (ACCESS EXCLUSIVE on ALTER) and for how long; it warns, never refuses. `kora doctor --production` adds `production-worker-delivery` (SQLite worker and `assets/sqlite3.wasm` in the build output, `.wasm` media type rules), `production-isolation-headers` (COOP/COEP are required only when the app itself needs `SharedArrayBuffer`; the `sqlite-wasm` adapter does not) and `production-runtime-storage`, and with `--url` a credential-free probe of the deployed server (`production-server-health`, `production-server-protocol`, `production-server-auth`) that times out cleanly and treats an unreachable network as a warning. `kora doctor --json` prints every check (`id`, `title`, `status`, `message`, `fix`) as one JSON document.
