Delivery visibility index (C2, first part). The server derives, for every collection, the fields an operation is filed under (`P(c)`): the scope and `sync` bindings, every field an access read rule names (recursively through `or` and `and`), the memberships collection's `userId` and `group`, and each group collection's `id` and owner field. A new `KoraSyncServer` option `deliveryPartitions: { [collection]: string[] }` adds fields for providers whose scopes the schema cannot show (a `TokenAuthProvider` scope is an arbitrary map). The plan's fingerprint is stored in `kora_server_meta` (`delivery_partition_fields`); the stores gain `setDeliveryPartitions` and `getDeliveryPartitionState`. The index only narrows what is read and never decides delivery: the session's filter stays the single authority.

The index itself (C2.2): a `kora_delivery_partitions (partition_key, delivery_seq)` table (`WITHOUT ROWID` on SQLite, an in-memory sorted array per key on the memory store) and two composite indexes on `operations`, `idx_collection_delivery (collection, delivery_seq)` and `idx_node_delivery (node_id, delivery_seq)`. On Postgres they are built with `CREATE INDEX CONCURRENTLY` in the background after startup, and an index a crash left `INVALID` is dropped and built again. A changed partition plan, a new or dropped table resets the contiguous frontier (`delivery_partitions_through`) and the index is backfilled in the background in chunks of 5,000 operations, resumable and idempotent. Until the index is complete sessions keep reading through the global scan.

Writes (C2.3): every apply path (`applyRemoteOperation`, the conditional apply, route apply and server-built transactions) files the operation's rows in `kora_delivery_partitions` in the same transaction as the operation and its scope snapshot, under the keys of its pre and post snapshots. An operation the index cannot place (no snapshot, an unknown post image, a snapshot gap) is filed under the collection's unknown key. The frontier advances by compare-and-set only on an instance running the stored plan, including for sequences reserved without an operation. Quarantining an unreadable operation and a replace-mode restore remove their rows.

Reads (C2.4): `getOperationsAfterDeliveryIn(sources, after, limit)` on all three stores returns the operations filed under a set of partition keys, whole collections and nodes, merged in delivery order, with `complete` and `coveredThrough` (the frontier read before the query). Postgres probes each source with `LATERAL`; SQLite and the memory store merge per-source seeks. More than `MAX_DELIVERY_SOURCES` (256) sources, an index under another plan, or an invalid composite index answer `complete: false`. A scoped session without access rules or held writes now scans through the index and reads the tail above `coveredThrough` through the global scan; `filterDeliveryChunk` still judges every operation, so the result is identical to the global scan. A scope field outside the partition plan reads its collection whole and logs `delivery.partition_miss`.
