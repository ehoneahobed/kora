Version gate, stage 1 (`docs/design/version-gate.md`): one build of an app writes a browser database at a time. When a tab running a newer build opens, every tab of an older build stops writing before the newer tab writes, and no write the older tab confirmed is lost.

- Every tab declares `{ build, format, openSeq, tabId }` and holds a Web Lock named after it (`kora-tab:<db>:<identity>`) for its life; `navigator.locks.query()` is the roster, so silent followers and tabs that have not processed a message are seen. `openSeq` comes from an IndexedDB counter (`kora-gate`), never the clock. The ordering key is `(format, openSeq)`.
- A tab retires when it learns of a tab of another build with a higher key (discovery, a `kora-build-hello`, or the leader heartbeat, which now carries the leader's identity): it refuses new writes with `BuildSupersededError` (`code: 'BUILD_SUPERSEDED'`, retriable, carries `collection` and `operation`, never data), waits for every write it started, makes them durable (IndexedDB fallback: a failed barrier keeps the tab lock and retries; `SNAPSHOT_SUPERSEDED` does not hold it), gives up its storage roles (a leader first waits for its old-build followers to retire, then stops its worker; a follower withdraws its queued promotion) and releases its tab lock. Reads keep working through the newer build's leader.
- A tab opens storage only when no tab of another build with a lower key holds its tab lock; there is no deadline. After 10 s it reports `store:build-gate-waiting` (`reason: 'live-writer' | 'unsaved-writes' | 'legacy-build'`). A tab granted the leader lock checks the roster first and releases it unopened when a newer build is listed, so an old-build worker never starts after a newer tab appeared.
- Page lifecycle: OPFS tabs release their tab lock on `freeze` / bfcache `pagehide` after the leader lock. IndexedDB-fallback tabs with a write outside a stored snapshot keep their storage roles and tab lock until the snapshot holding it is stored (behaviour change: a dirty fallback leader is no longer suspended before its snapshot is saved).
- Missing coordination APIs fail closed: without `BroadcastChannel`, one tab at a time (`kora-db:<db>`, `store:tab-exclusive`); without Web Locks, storage open refuses with `TabCoordinationUnavailableError` unless `allowUncoordinatedTabs` is set. Outside a browser page the gate does not apply.
- Kora storage format `1` (`KORA_STORAGE_FORMAT`): stored once in `_kora_meta('storage_format')` and in the IndexedDB snapshot version record, never written by older code. A newer stored format refuses the open (`StorageFormatAheadError`, `store:format-ahead`) before any DDL or write (`--kora:format-ceiling` DDL directive).
- A leader running a pre-gate build is detected by the gated-leader marker lock it does not hold; the newer tab waits for its leader lock (`store:legacy-build-detected`). Builds without a build id fall back to a schema fingerprint (`store:build-unidentified`).
- New: `VersionGate`, `Store.trackWrite()`, `StorageAdapter.getVersionGate()`, adapter options `versionGate`, `build`, `allowUncoordinatedTabs`, and events `store:format-ahead`, `store:build-gate-waiting`, `store:build-unidentified`, `store:legacy-build-detected`, `store:tab-exclusive`, `store:tab-coordination-unavailable`.
