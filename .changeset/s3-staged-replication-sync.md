Staged replication (first-visit parity S3). A device's first sync of a view (delivery base 0, at least `bulkReplication.minOperations` = 2000 server operations, more than one batch) is applied into a scratch replica (`SyncStore.beginBulkReplication`) through the same one-transaction batch path as before (decrypt, verify, transforms, quarantine, chained watermark), and merged into the live database once with the final batch. The live delivery watermark and completion mark are written by the merge, so a crash, reload, stop, view switch or failed merge leaves the live database where it was and the next session replicates again from its watermark; nothing is dropped. A batch that narrows the view, retracts records or fails to apply in the replica merges the clean staged prefix (watermark of the prefix included) and the rest of the stream is applied directly on the same connection; a view change, stop, revocation or server rollback drops the replica and restores the live watermark. Events from the replica are buffered and replayed to the live listeners only after the merge commits. New `SyncConfig.bulkReplication` (`false` turns it off), the `BulkReplication` types, and the events `sync:staging-started`, `sync:staging-merged` and `sync:staging-discarded`.
