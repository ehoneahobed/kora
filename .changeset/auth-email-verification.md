Email verification in `createKoraAuthServer({ emailVerification: { url, send } })`: a single-use link is sent at sign-up (unless `sendOnSignUp: false`) and on `POST /auth/email/send-verification`, and `POST /auth/email/verify` marks the address verified. Only a SHA-256 of each token is stored, in the SQLite or Postgres user store's database (`getEmailVerificationStore()`); a link verifies only the account it was sent for, opened while signed in to it (so whoever registered someone else's address cannot get the owner to verify it by clicking the email), and only while the account still has that address; it expires after 24 hours and ends the user's other links. Sending is limited to 3 emails per user per hour, counted atomically; delivery failures are reported; sign-up never waits for the email. Production refuses an in-memory verification store. Clients get `authClient.sendVerificationEmail()`, `authClient.verifyEmail(token)` and `currentUser.emailVerified`, also on `useAuth()` in React, Vue and Svelte. Sign-in is never blocked on verification; sharing, organization invitations and OAuth linking check `emailVerified`. `oauth.autoLinkVerifiedEmail` now also requires the existing account to have verified the address, and `AdminApi.updateUser` resets `emailVerified` when it changes the address (unless it sets `emailVerified` too).

Breaking (experimental API): `EmailVerificationManager` is now `new EmailVerificationManager(userStore, { url, send, ... })` with `send(userId, reason)` and `verify(token, userId)`; it no longer returns tokens in responses, and `EmailVerificationStore` stores token hashes (`take`, `countSend`, `deleteForUser`, `deleteExpired`); `UserStore` gains an optional `markEmailVerifiedIfEmail`. `VerificationTokenExpiredError` and `VerificationTokenNotFoundError` are removed (results carry `VERIFICATION_TOKEN_EXPIRED` and `VERIFICATION_TOKEN_INVALID`).
